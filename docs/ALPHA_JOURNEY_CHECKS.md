# Reproducible alpha model journeys

These local regression checks cover the same fictional article across import, private files, browser-recovery state, checkpoints, and WordPress handoff. They are not a claim that a real Word document, Google Docs clipboard, mobile browser, screen reader, or saved WordPress post passed acceptance.

## Run without external services

From the repository root, using the project's supported Node version and Python 3:

```sh
npm run test:alpha-journey
node --test tests/inline-underscores.test.js
npm test
npm run check
```

The targeted journey command runs six scenarios. It uses Python standard-library ZIP and HTML readers in memory, without writing downloaded articles, installing dependencies, opening a network connection, or invoking AI. The complete test command includes these scenarios automatically. Nothing uses GitHub Actions or cron.

## Scenario matrix

| Imported source | Explicit image choice after restore | Additional check |
| --- | --- | --- |
| Markdown with page fields | Images remain literal text | Cancel then restore, retain previous checkpoint, remove recovery |
| Markdown with page fields | Linked images on | Same journey with one explicit HTTPS image reference |
| Structured article JSON | Images remain literal text | Same journey, preserving private review notes |
| Structured article JSON | Linked images on | Same journey with the image choice deliberately reselected |
| Structured article JSON | Default | Refused checkpoint keeps current writing and the stored copy; correction permits retry |
| Markdown with page fields | Default | Storage-full keeps the last good copy while a fresh file and kit retain newer edits |

All private markers in the fixture are fictional. Expected visible text is specified independently, not generated by the converter under test. The fixture includes Unicode, literal identifiers, emphasis, a safe link, nested lists starting at 4, a table with a literal pipe, a quote, code containing angle brackets, an image reference, and an exact final marker.

## Assertions across module boundaries

- Import retains exact article and page fields.
- A version-1 private file round-trips source notes and review questions.
- The recovery model writes nothing until its start method is explicitly invoked. A later session does not automatically open saved writing.
- Cancellation keeps current writing and the stored copy. Deliberate restoration checkpoints the different current article and clears the harness's approval state.
- Approval, pending import data, and export choices do not enter the stored browser copy. The image-export option is chosen again after restoration.
- Python independently reads all six actual ZIP members, checks their CRCs, and extracts the generated block HTML without executing it or loading resources.
- Golden text, Unicode, final markers, list starts, table cells, links, code, and the selected image mode survive the handoff.
- Article files contain no fictional private source, audience, purpose, review, pending-import, or export-choice marker.
- Removing recovery cannot resurrect a copy after another edit. A full-storage failure keeps open writing exportable while preserving the older saved copy.

Recovery storage and Web Locks are controlled in-memory substitutes here. Import application and restore callbacks are a model harness, not a full browser UI. Its approval and checkpoint assertions verify those supplied callback contracts, not a new real-browser approval test.

## Fidelity regression found by this corpus

The first run caught literal `ALPHA_END_4827` becoming `ALPHAEND4827` in rendered output. The inline reader had interpreted an underscore pair inside a word as emphasis. Simple underscore pairs now use bounded Unicode flanking checks, preserving identifiers while retaining ordinary standalone emphasis. Independent HTML and Word XML readers check the corrected output. Escapes, code, links, asterisk emphasis, exact offsets, and near-limit identifier runs also have focused cases.

Reference: [CommonMark 0.31.2, emphasis and strong emphasis](https://spec.commonmark.org/0.31.2/#emphasis-and-strong-emphasis), especially examples 374 and 375 on intraword underscores. This targeted correction does not make Draft to Page a complete CommonMark implementation. Complex delimiter constructions remain outside its limited subset and can stay literal.
