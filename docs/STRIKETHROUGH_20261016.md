## Reproduced problem and supported behavior

The unchanged licensed Word fixture `word-strikethrough.docx` strikes through "Today's Special: Salmon", followed by ordinary " Sold out". It previously imported the words with a simplification warning. This change retains the actual struck text, rather than only removing its warning. The corpus now independently checks both HTML exports and Word XML before classifying that case as preserved. The fixture hash and upstream provenance are unchanged.

- Exactly two matching tildes wrap nonempty text on one line. Strikethrough composes with supported emphasis, code and safe link labels. Original UTF-16 positions, CRLF line numbers, code/URL protection, 16-level nesting and per-line work limits remain. Single tildes, runs of three or more, malformed, multiline and excessive structures stay literal. This is a bounded subset, not full GitHub Flavored Markdown support.
- Shared inert DOM/HTML output uses semantic s elements; Word emits direct single-strike run properties. Supported body headings, lists, table cells and quotations use the same inline model. Article exports keep existing private-field exclusions. Source HTML stays inert and no image is loaded.
- Word import handles ordinary direct on/off values and supported default/paragraph/character style chains. OOXML style strike values toggle, style false leaves prior state, and direct run values are absolute. Paragraph-mark formatting does not style all text. Invalid strike values reject conversion. Double strike retains text with an explicit loss warning rather than inventing a single line. Existing underline/vertical-alignment loss disclosures remain. This is not general Office layout or every producer's style acceptance.
- HTML s/strike elements and ordinary inline line-through styles are retained, including declaration order and important priority for decoration line/shorthand. Double strike is simplified with a warning; dotted/dashed/wavy line styling gets a visible simplification warning. Multiline or ambiguous serialization uses the existing loss disclosure and complete literal fallback. Imported H1/title fields remain plain and receive a targeted strike-loss warning. Imported blockquotes retain their earlier disclosed plain-quote simplification. HTML ins/del remains blocked as possible tracked changes.
- Plain clipboard data still escapes punctuation through the bounded serializer, so literal tildes do not acquire formatting. Insertion also escapes tildes in an imported plain title. Guided link/image edits continue to reject partial styled tokens; links inside strike retain their surrounding-format guard.
- Reviews stop falsely reporting supported strike as unavailable. Remaining recognized unsupported double-tilde-like syntax receives a current literal-formatting explanation. Existing source-selection, approval, file formats, browser recovery consent and linked-image choices are unchanged.

All 15 corpus cases passed in a preliminary browser run: three preserved, seven disclosed, four rejected and one sampled. The strikethrough case verifies the actual mark in WordPress HTML, HTML source and Word XML, with UI staging/apply checks.

## References and limits

The implementation uses [Microsoft's strike element documentation](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.strike?view=openxml-3.0.1) for single-strike/direct properties and toggle semantics. [GitHub's extension description](https://github.github.com/gfm/#strikethrough-extension-) is a syntax reference only: Draft to Page intentionally supports exact double tildes on one line, and emits s rather than accepting tracked-deletion markup. These references were checked October 16, 2026.

Document-default-on strikethrough combined with paragraph or character style strike declarations is conservatively rejected unless each affected run supplies an explicit on/off value. Microsoft documents compatibility differences for this combination; the converter does not guess which appearance was intended. Unambiguous defaults and ordinary direct formatting remain supported. See [the Microsoft toggle compatibility note](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/f7130225-2368-48f3-acae-a9d278d0fb25).

A preliminary genuine WordPress run exposed a rendering difference in the new Word fixture: the stored straight apostrophe is displayed as a typographic apostrophe. The case now checks exact original stored text/marks and the separately specified rendered text/marks. Only this observed fixture expectation changes; punctuation is not normalized across the suite. A separate raw-text evidence flag is required. The initial full gate failed on that newly added expectation and is not counted as an acceptance pass. A final full stable-source rerun is required.

No provider activation, fees, tracking, outreach, persistent state, dependency, Actions, cron or hosting change is introduced. Native Cloudflare Git deployment remains the release path.
